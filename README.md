# Меняемся

«Меняемся» — веб-сервис для безденежного обмена товарами и услугами. Пользователи размещают лоты, указывают, что хотят получить взамен, и находят участников с подходящими предложениями.

Проект команды `"Деловые люди"` по предмету `"Проектный практикум"`, 7 семестр ИРИТ-РТФ УрФУ.  
Заказчик: `"ИТого"`.

## Для кого

Сервис предназначен для тех, кто хочет обменять ненужные вещи или свои услуги на что-то полезное: студентов, семей, специалистов, фрилансеров и сторонников осознанного потребления.

## Возможности

- Регистрация, подтверждение почты, вход и восстановление пароля.
- Личный кабинет со своими лотами, завершёнными обменами, отзывами и рейтингом; просмотр профилей других участников.
- Настройки имени, региона, контактов и аватара.
- Лоты товаров и услуг с описанием, фотографиями, категорией, регионом, способом передачи и ориентировочной стоимостью.
- Пошаговое создание и редактирование лота, выбор обложки, сохранение текстового черновика, отправка на модерацию, удаление и повторная публикация.
- Несколько вариантов обмена одновременно: конкретные лоты, категории, свободное описание пожеланий и готовность рассмотреть предложения участников. Можно выбрать до 10 лотов и до 10 категорий. Текст пожеланий ограничен 300 символами и не разделяется на теги по запятым или пробелам.
- Галерея фотографий и отдельные действия для владельца лота.
- Центр уведомлений с категориями, отметкой прочтения и очисткой списка.
- Административная панель для управления пользователями и категориями, заморозки и разморозки аккаунтов.
- FAQ с поиском по вопросам и правила сервиса.

Интерфейс адаптирован для компьютеров, планшетов и телефонов, поддерживает светлую и тёмную темы. Защищённые разделы доступны после входа, административная панель — только администраторам.

## Статус продукта

Продукт находится в разработке. Авторизация, данные профиля и часть действий с лотами и категориями подключены к серверу. Списки лотов в кабинетах, отзывы, завершённые обмены и уведомления пока используют локальные данные. Карточка ИИ-оценки показывает фиксированную рекомендацию.

Создание лотов для обычных пользователей ограничено доступностью категорий. Сохранение изменений фотографий и пожеланий существующего лота, список пользователей в админ-панели и доставка реальных уведомлений требуют доработки сервера.

## Планируемые возможности

- Общедоступный каталог с поиском и фильтрами.
- Персональные рекомендации лотов.
- Автоматическая оценка рыночной стоимости.
- Предложения обмена и переписка между участниками.
- Подтверждение завершения обмена, отзывы и рейтинг на основе реальных сделок.
- Жалобы и модерация лотов.
- Серверные уведомления о сообщениях, предложениях, результатах модерации и состоянии обменов.

## Технологический стек

- **Frontend:** Next.js 16.4.2 (App Router), React 19.2.3, TypeScript 5.9.3, SCSS Modules, архитектура Feature-Sliced Design.
- **Backend:** Java 21, Spring Boot 3.5, Spring Security, Spring Data JPA, JWT.
- **База данных:** PostgreSQL 17, миграции Liquibase.
- **Запуск:** Docker Compose; frontend также можно запускать локально через npm.

## Запуск проекта

Понадобятся Docker и Docker Compose. В корне репозитория создайте `.env` из примера:

```bash
cp .env.example .env
```

Заполните учётные данные PostgreSQL, настройки SMTP и отправителя писем, секреты access- и refresh-токенов. Значение `POSTGRES_DB` должно совпадать с именем базы в `SPRING_DATASOURCE_URL`. Для запуска через Compose адрес базы — `db:5432`, публичный адрес приложения — `http://localhost:3000`. Файл `.env` содержит секреты и не должен попадать в Git.

Запустите сервисы из корня репозитория:

```bash
docker compose up --build
```

При первом запуске PostgreSQL создаёт базу данных, а backend применяет миграции Liquibase.

| Сервис | Адрес |
| --- | --- |
| Приложение | http://localhost:3000 |
| Backend API | http://localhost:8080/api/v1 |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |

Просмотр журналов и остановка сервисов:

```bash
docker compose logs -f db backend frontend
docker compose down
```

База данных хранится в Docker volume `postgres_data`, загруженные изображения — в `uploads_data`. При обычной остановке данные сохраняются; `docker compose down -v` удаляет их вместе с этими volume.

## Локальный запуск frontend

Понадобятся Node.js и npm. Из корня репозитория запустите backend и базу данных:

```bash
docker compose up db backend --build
```

В отдельном терминале запустите frontend:

```bash
cd frontend
npm ci
npm run dev
```

Приложение доступно на http://localhost:3000. Адрес сервера задаётся переменной `NEXT_PUBLIC_API_URL`, по умолчанию — `http://localhost:8080`. Пример настройки находится в `frontend/.env.example`; при необходимости создайте на его основе `frontend/.env.local`.

Для локальной production-сборки из директории `frontend`:

```bash
npm run build
npm start
```
