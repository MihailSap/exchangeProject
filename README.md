# Меняемся

Проект команды `"Деловые люди"` по предмету `"Проектный практикум"`, 7 семестр ИРИТ-РТФ УрФУ.  
**Заказчик:** `"ИТого"`.

«Меняемся» — веб-сервис для безденежного обмена товарами и услугами. Проект помогает найти человека с взаимным интересом, договориться об условиях обмена и безопаснее взаимодействовать благодаря профилям, отзывам и модерации.

## Цель и аудитория

Сервис рассчитан на людей, которым проще обменять ненужную вещь или услугу, чем продавать её и покупать нужное за деньги. Среди основных пользователей — семьи, студенты, молодые специалисты, фрилансеры, самозанятые и сторонники осознанного потребления.

## Возможности по техническому заданию

Целевой функционал проекта включает:

- регистрацию по email, подтверждение адреса, вход и восстановление пароля;
- профили пользователей с регионом, контактами и рейтингом;
- публикацию лотов двух типов: товар и услуга, с фотографиями, категорией, регионом, способом передачи и ориентировочной стоимостью;
- описание того, что пользователь хочет получить взамен;
- поиск по каталогу, фильтры и автоматические рекомендации с учётом интересов, региона, стоимости и рейтинга;
- ориентировочную оценку стоимости лота, которую пользователь может принять или изменить;
- предложения обмена, переписку по лоту и фиксацию результата обмена;
- отзывы и рейтинг после завершения обмена;
- жалобы, модерацию лотов и инструменты управления аккаунтами;
- уведомления о предложениях, сообщениях, действиях модераторов и состоянии лотов.

Гости могут просматривать каталог и искать лоты. Создание лотов, предложения обмена и другие действия от имени пользователя требуют авторизации. В техническом задании также предусмотрены роли модератора и администратора.

## Текущая реализация

Проект находится в разработке. Сейчас backend содержит REST API для аутентификации, пользователей, лотов, категорий, регионов, файлов и административной заморозки аккаунтов. Подготовлены PostgreSQL, JPA и миграции Liquibase. Frontend — начальный Next.js каркас с домашней страницей-заглушкой.

Рекомендации, оценка стоимости, обменные предложения, чат, отзывы, жалобы и центр уведомлений остаются целевым функционалом из ТЗ: готовых модулей и пользовательского интерфейса для них в текущем коде пока нет.

## Технологии

- **Frontend:** Next.js App Router, React, TypeScript; структура кода подготовлена по Feature-Sliced Design.
- **Backend:** Java 21, Spring Boot 3.5, Spring Security, Spring Data JPA, JWT.
- **База данных:** PostgreSQL 17; схема обновляется через Liquibase.
- **Среда запуска:** Docker Compose.

## Структура репозитория

```text
backend/       Spring Boot приложение и Dockerfile
frontend/      Next.js приложение и Dockerfile
compose.yaml   совместный запуск frontend, backend и PostgreSQL
.env.example  пример переменных окружения
```

## Запуск всего проекта

Нужны Docker и Docker Compose. Создайте корневой `.env` из примера, если его ещё нет, затем заполните значения, выданные backend-разработчиком:

```bash
cp .env.example .env
```

В `.env` задаются имя и учётные данные PostgreSQL, JDBC URL, публичный адрес frontend и JWT-секреты. Для Compose используйте `POSTGRES_DB=exchange_project_db` и JDBC URL `jdbc:postgresql://db:5432/exchange_project_db`; имя в обеих настройках должно совпадать. Для локального запуска frontend значение `APP_PUBLIC_URL` должно быть `http://localhost:3000`. Не добавляйте `.env` в Git.

Соберите образы и запустите сервисы из корня репозитория:

```bash
docker compose up --build
```

При первом запуске Docker скачает образы, PostgreSQL создаст базу, а backend применит миграции Liquibase.

| Сервис | Адрес |
| --- | --- |
| Frontend | http://localhost:3000 |
| Backend API | http://localhost:8080/api/v1 |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |

Чтобы смотреть журналы сервисов в отдельном терминале:

```bash
docker compose logs -f db backend frontend
```

Остановить контейнеры можно сочетанием `Ctrl+C` или командой `docker compose down`. Данные PostgreSQL сохраняются в именованном Docker volume `postgres_data`. Команда `docker compose down -v` удаляет этот volume вместе с данными базы.

## Локальная разработка frontend

Для локальных команд понадобятся Node.js с npm, Java 21 и Maven. PostgreSQL можно оставить в Docker.

Frontend можно запускать отдельно в режиме разработки:

```bash
cd frontend
npm ci
npm run dev
```

Для локальной работы backend и базы запустите `docker compose up db backend --build` из корня репозитория. Frontend dev-сервер будет доступен на http://localhost:3000.

Проверки frontend:

```bash
cd frontend
npm run lint
npm run typecheck
npm run build
```

Проверка backend:

```bash
cd backend
mvn test
```

## API

Базовый префикс API — `/api/v1`. Основные группы маршрутов: `/auth`, `/users`, `/lots`, `/categories`, `/regions`, `/files` и `/admin`. Полный список методов и моделей можно посмотреть в Swagger UI после запуска backend.
